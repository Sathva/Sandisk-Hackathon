# Per-Die Interpretability for Official Model A and Model B

Closes the one required deliverable that was previously answered about the wrong
model. Generated by `src/interpretability/model_ab_attribution.py`.

The problem statement asks for:

> "Interpretability output: per-die feature importance + spatial contribution
> visualization (Model A), plus block reading pattern analysis (Model B)"

The pre-existing suite in `src/interpretability/` attributes **Model F**, which is the
project's strongest architecture but is not one of the two mandated deliverables.
Everything below attributes Model A and Model B directly.

## Method

Both official models are LightGBM boosters, so exact TreeSHAP is available natively
through `predict(..., pred_contrib=True)`. No sampling, no surrogate model, no `shap`
dependency. LightGBM returns `n_features + 1` columns, the last being the base value,
and each row sums to the model's raw margin. That identity is verified rather than
assumed:

| Model | Features | Additivity max abs error (log-odds margin) |
| :--- | :---: | :---: |
| Model A | 519 | 2.04e-14 |
| Model B | 555 | 2.31e-14 |

**Selection.** All 3,309 dies flagged by Model A or Model B at their own F1-optimal
thresholds, plus 5,000 uniformly random unflagged controls, giving 8,309 explained
dies out of 185,126 eligible. Ground-truth labels are **not** used to select dies, so
the "no label peeking" guarantee holds without qualification.

**Score semantics.** Both models output genuine probabilities from a sigmoid over the
tree margin, so unlike the rank-blended Model F these can be read as calibrated
failure probabilities.

### On accuracy

Accuracy is reported because the problem statement asks for it, but it is close to
uninformative here. Predicting PASS for every die scores **0.96444 accuracy while
finding zero defects**. Model B is *less* accurate than Model A while being clearly
better, because it trades precision for the recall that actually matters. This is
direct evidence for the imbalance-handling criterion: neither model collapses to the
trivial solution, and both are selected on AUC-PR and positive-class F1 instead.

# Extension: the 3-Engine Stacks

Generated by `src/interpretability/model_ab_stack_attribution.py`. The section above
explains each official model's LightGBM booster; this extends attribution to all
three engines, so it covers the stacks that are quoted as the Official Model A and
Official Model B deliverables.

## Why the three engines' SHAP values are not summed

The official stacks blend in **probability** space:

```
p_stack = 0.50*p_lightgbm + 0.30*p_catboost + 0.20*p_xgboost
```

TreeSHAP is exactly additive in each engine's own raw **log-odds margin**, and the
sigmoid linking margin to probability is non-linear. So the three engines'
margin-space SHAP values do **not** sum to a decomposition of the stack probability.
Each engine is decomposed separately; the blend-weighted row below averages per-engine
*shares*, which are scale-free ratios, and is labelled as an aggregate of three
decompositions rather than a decomposition of the stack. Per-die drivers come from
LightGBM, which carries the largest weight at 0.50. This mirrors the treatment of
Model F, where rank blending forces the same choice.

## Additivity, verified per engine

| Engine | Model A | Model B |
| :--- | :---: | :---: |
| LightGBM | 2.04e-14 | 2.31e-14 |
| CatBoost | 8.88e-16 | 1.78e-15 |
| XGBoost | 1.19e-05 | 8.81e-06 |

XGBoost's larger residual is expected: it accumulates contributions in float32, so
1e-5 is at the limit of single precision and is not an error in the decomposition.

## The robustness argument this produces

The three engines are architecturally different: leaf-wise histogram trees, symmetric
oblivious trees, and depth-wise histogram trees. They were fitted independently. Yet
they agree closely:

- All three rank `max_rolling_mean_400` as the single most influential feature in
  Model B, at 0.355, 0.310 and 0.373 mean |SHAP| respectively.
- All three place the same four block features in the top four.
- The sub-die block share lands within 0.4 percentage points across all three
  (7.0%, 7.4%, 7.3%).

Three independent learners converging on the same evidence hierarchy is stronger
support for the block channel's causal role than any single model's ranking, and it
is the cleanest available answer to the A-to-B improvement question.

# Accuracy Coverage in the Submission Report

The problem statement asks the comparison analysis to report "F1, AUC-PR, accuracy".
Accuracy was present in the metrics JSONs but appeared in no report table. It now
appears in all four model performance tables of
`reports/FINAL_SUBMISSION_REPORT.pdf`, 26 rows in total:

| Report section | Table | Rows |
| :--- | :--- | :---: |
| 5.2 | Official Model A performance | 4 |
| 6.2 | Official Model B performance | 4 |
| 11 | Grand Champion Hybrid comparison | 7 |
| 12 | Master benchmark summary | 11 |
| 17A.2 | Model A to Model B comparison | as a metric row |

## How the values were obtained

Four cases were measured directly from the saved boosters: Model A and Model B, each
as a single LightGBM booster and as a 3-engine stack. For the remaining rows accuracy
is derived from that row's own precision and recall together with the fixed
population of 185,126 eligible dies and 6,584 true failures:

```
TP = recall x 6,584
FP = TP x (1/precision - 1)
accuracy = (TP + 178,542 - FP) / 185,126
```

Two independent checks confirm the derivation rather than taking it on trust. It
reproduces the four directly measured values to within 1e-5, and the false-positive
counts it implies match the report's own False Alarms column exactly for every row
where that column exists (758, 681, 800, 749, 708).

## A consistency error this surfaced

Correcting the precision and recall of the two official stacks left the False Alarms
column in section 11 stale. It read 151 and 158 for Model A and Model B, but the
corrected operating points imply 115 and 659. Both cells were repaired, and all seven
rows in that table are now internally consistent.

## What the column shows

Accuracy spans **0.9644 to 0.9768** across every model in the project. The No-Skill
baseline, which detects zero defects, sits within **1.24 points** of the Grand
Champion, and Model B is marginally *less* accurate than Model A while being clearly
the better screen. That is stated in a note beneath the master table, which turns a
weak metric into supporting evidence for the imbalance criterion rather than a number
that flatters the trivial solution.
